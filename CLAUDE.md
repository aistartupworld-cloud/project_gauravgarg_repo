# SecureGate — root CLAUDE.md

SecureGate is a compliance audit, findings and remediation platform (business case BC-AINE-015).
This file is the root of a layered CLAUDE.md hierarchy. Module and folder files refine it; they never contradict it.
`AGENTS.md` is the table of contents for every agent-facing file in the repo.

## Prime directives

1. **Specs are the source of truth.** Read `specs/app_spec.md` and the feature spec before touching code.
   When code and spec disagree, change the spec deliberately (in its own commit) and regenerate the code.
2. **No hand-written production code.** Production code, tests and migrations are generated by Claude Code agents.
   Humans edit specs, CLAUDE.md files, agent definitions, hooks, skills and commands only.
3. **PR-only merges.** Never commit to `main`. Work on `feat/*`, `fix/*` or `chore/*`, get an evaluator review,
   then merge with `git merge --no-ff` so the PR boundary stays visible in history.
4. **Synthetic data only.** Seed data and fixtures use invented people, hosts and assets (`*.example.internal`,
   `ASSET-xxxx`). Never paste real customer or employer data.

## Architecture in one paragraph

Layered TypeScript backend under `server/src`: `controllers` (HTTP + auth boundary) → `services` (use cases,
transactions, actor checks) → `repositories` (SQL over `node:sqlite`) → `domain` (pure rules, no I/O).
`infrastructure` holds logging, clock, DB connection and migrations runner. React SPA under `web/src` talks to
`/api/*` only. Layering is enforced by `.dependency-cruiser.cjs` and `tests/architecture/*`.

## Domain rules agents must never break

- Audit lifecycle: `PLANNED → IN_PROGRESS → FINDINGS_RECORDED → REMEDIATION_IN_PROGRESS → CLOSED`. Anything else throws
  `InvalidAuditStateException` (AC-03). A CLOSED audit is read-only (NFR-08).
- Finding lifecycle: `OPEN → AWAITING_REVIEW → REMEDIATED | RE_OPEN`, `RE_OPEN → AWAITING_REVIEW`.
- **Separation of duties:** the finding owner can never approve their own remediation, and neither can the auditor
  who raised it. Every code path that sets `REMEDIATED` calls `assertSeparationOfDuties` (NFR-08).
- SLA arithmetic is integer days on UTC calendar dates. No floating point, no `Date` millisecond division (NFR-01).
- Audits, findings, finding events, evidence and decisions are **append-only** (NFR-02). Published control
  versions are immutable (AC-01). Migrations are append-only (NFR-05). DB triggers back all three.
- Logs are structured JSON with `correlationId`, and `auditId`/`findingId` when known. IPs, hostnames, credential
  references and asset identifiers are masked before a log line is written (NFR-03, NFR-06).

## Tests

- Every acceptance criterion `AC-NN` and NFR `NFR-NN` has at least one test whose name contains the tag, e.g.
  `it('[AC-05] computes CRITICAL due date as +7 days', ...)`. `npm run ac:trace` fails when one is missing.
- Write the failing test first (see `docs/tdd.md`). Domain rules get unit tests; endpoints get API tests.

## When an agent fails

Fix the environment, not the generated code: tighten the spec, the hook, the skill or this file, then regenerate.
Record recurring mistakes in `docs/knowledge-deposits.md`.
